# Как найти центр и радиус отказной зоны

Статус: план измерения, код и модели не изменены.

Связанный дизайн профиля:
[LOCALIZED_INVERSION_DESIGN.md](LOCALIZED_INVERSION_DESIGN.md).

После дополнительного расследования этот план расширен в
[PROBLEM_ZONE_LOCALIZATION.md](PROBLEM_ZONE_LOCALIZATION.md). Новый документ
разделяет detection, residual writing, policy routing и actual weight-edit
leverage; именно последняя карта должна определять окно Heretic.

## 1. Главный принцип

Наблюдаемый пик активации ещё не означает, что этот слой причинно создаёт отказ.
Он может:

- распознавать вредность запроса;
- передавать уже сформированное решение;
- только форматировать отказ;
- компенсировать более раннюю активацию;
- коррелировать с лексикой обучающего набора.

Поэтому поиск делится на три уровня:

1. **статистическая локализация** — дешёво предлагает кандидатов;
2. **причинное вмешательство** — проверяет окно;
3. **поведенческая валидация** — подтверждает изменение смысла ответа и цену.

Пропуск второго уровня превращает красивый график активаций в недоказанную
историю.

## 2. Что текущий код теряет

В `src/heretic/main.py:571-588` вычисляется:

```text
delta_l = bad_mean_l - good_mean_l
v_l = normalize(delta_l)
```

После этого исходные средние удаляются (`src/heretic/main.py:591`).

Следствия:

- норма `||delta_l||`, то есть возможная величина всплеска по слоям, теряется;
- все направления становятся единичными и визуально одинаковыми по масштабу;
- `max_weight_position` ищется только по итоговому black-box score;
- текущий журнал не позволяет восстановить исходную послойную амплитуду.

Для диагностики необходимо отдельно сохранять агрегаты до нормализации. Полные
тексты или активации сохранять необязательно.

## 3. Замороженные данные и метрики

До любого скана фиксируются:

- train/eval prompt IDs и порядок;
- generation seed и параметры декодирования;
- версия базовой модели;
- версия направления;
- scorer и его версия;
- список категорий;
- harmless/tech-sensitive контроль.

Основные итоговые метрики:

1. смысловые `REFUSAL`, `SOFT`, `COMPLY`;
2. переходы каждого prompt ID между вердиктами;
3. относительный рост perplexity;
4. ложные отказы на harmless и tech-sensitive;
5. разбивка по категориям.

KeywordRate допустим только как быстрый диагностический сигнал. Он не должен
решать, какое окно победило.

## 4. Статистический предскан

Для каждого промпта и слоя следует собирать residual activation как минимум в
двух представлениях:

- последний токен пользовательского запроса;
- среднее или максимум по последним `N` токенам запроса.

Один последний токен может отражать chat-template сильнее содержания. Работа
по refusal SAE также отмечает сильную роль финальных chat tokens, поэтому
позицию токена надо учитывать явно, а не усреднять без проверки.

### 4.1 Сохраняемые скаляры

Для каждого слоя:

```text
raw_delta_norm
raw_delta_norm / mean_residual_norm
projection_mean_bad
projection_mean_good
projection_std_bad
projection_std_good
standardized_separation
```

Стандартизованная разделимость:

```text
d_l =
  (mean(z_bad) - mean(z_good))
  / sqrt((var(z_bad) + var(z_good)) / 2),

z = v_lᵀh_l.
```

Она полезнее голой нормы, потому что учитывает разброс активаций.

### 4.2 Кросс-валидированный probe

На активациях каждого слоя:

- регуляризованная логистическая регрессия;
- стратифицированная cross-validation;
- AUROC и balanced accuracy;
- отдельные результаты для категорий;
- перестановочный baseline.

Probe измеряет доступность информации, а не причинность. Высокий AUROC не
разрешает автоматически редактировать слой.

### 4.3 Устойчивость направления

Для случайных половин обучающих промптов считать:

```text
cos(v_l_split1, v_l_split2)
```

и bootstrap-интервалы для центра максимальной разделимости.

Если позиция пика прыгает между splits, локальное окно найдено ненадёжно.

### 4.4 Тематические направления

Отдельно сравнить:

- общее harmful направление;
- AdvBench;
- harm;
- restricted/consultation;
- другие достаточно крупные группы.

Для каждого слоя измерить косинусы и углы подпространств. Если консультационное
направление расходится с общим именно в слоях остаточных отказов, проблема
находится в направлении или составе train, а не в форме весовой кривой.

## 5. Причинный поиск окна: основной метод

Диагностическая интервенция должна повторять тот же тип изменения весов, который
будет использовать финальная модель. Простое удаление направления из residual
stream на inference может локализовать другой механизм, чем изменение
`o_proj/down_proj`.

### 5.1 Многошкальный coarse-to-fine поиск

Для модели с `L` слоями:

1. покрыть глубину неперекрывающимися окнами радиуса 4–5 слоёв;
2. в каждом окне испытать `A=1` и `A=2`;
3. выбрать окна с лучшим парным выигрышем refusal/perplexity;
4. разбить лучшие окна пополам;
5. повторять до радиуса 1–2 слоя;
6. вокруг победителя отдельно подобрать мягкость края.

Такой поиск лучше полного перебора всех `[start, end]`, число которых растёт как
`O(L²)`.

Для 40 слоёв первый проход из пяти окон шириной 8 даёт:

```text
5 окон × 2 амплитуды × число компонентов.
```

До полного корпуса можно использовать небольшой, но замороженный диагностический
набор. Финал всегда пересчитывается на полном eval.

### 5.2 Почему нужны две амплитуды

`A=1` проверяет удаление компоненты, `A=2` — инверсию. Если полезен только режим
около 2, гипотеза локальной инверсии получает прямую поддержку. Если достаточно
1, термин «инверсия» лишний: найдено локальное стирание.

После локализации можно проверить `A ∈ {0.5, 1.0, 1.5, 2.0, 2.5}` только в
лучших окнах.

### 5.3 Парные изменения на уровне промпта

Для каждого prompt ID фиксировать:

```text
base_verdict
window_verdict
beneficial_flip
harmful_flip
```

Полезные переходы:

```text
REFUSAL → SOFT
REFUSAL → COMPLY
SOFT → COMPLY
```

Нежелательные переходы нельзя сводить только к refusal rate:

```text
связный ответ → бессвязный ответ
правильный ответ → фактическая деградация
harmless COMPLY → REFUSAL
```

Для долей использовать Wilson/Clopper-Pearson интервалы, для парного сравнения
вердиктов — McNemar или bootstrap по prompt ID.

## 6. Ускорение поиска кандидатов

### 6.1 Attribution patching как фильтр

Attribution patching оценивает множество компонентов двумя forward passes и
одним backward pass, но является линейным приближением. В опубликованных
исследованиях оно может переоценивать нелинейные эффекты и давать false
negatives.

Правильное применение:

1. получить дешёвый рейтинг слоёв/компонентов;
2. не принимать его за итог;
3. причинно проверить верхние кандидаты настоящей интервенцией.

Нельзя использовать KL от исходной модели как единственную
дифференцируемую цель в нулевой точке: там градиент может быть нулевым.

### 6.2 Случайные гладкие маски и sparse regression

Альтернативный способ, если один trial очень дорог:

1. сгенерировать набор случайных гладких масок по слоям;
2. применять малую амплитуду с разными знаками;
3. измерять парное изменение differentiable proxy и perplexity;
4. восстановить послойные коэффициенты group-lasso или sparse Bayesian
   regression;
5. причинно проверить найденные окна.

Это compressed-sensing предфильтр. Он предполагает приблизительную аддитивность
и потому не заменяет проверку.

### 6.3 Последовательное уточнение

После каждого проверенного окна обновлять модель кандидатов:

- центр;
- log-radius;
- амплитуда;
- компонент;
- неопределённость эффекта.

Следующий тест выбирать по expected improvement с учётом цены perplexity.
Это полезнее слепого Optuna на всей глубине, но только после первого
многошкального покрытия, иначе Bayesian search может рано зафиксироваться на
случайном пике.

## 7. Поиск взаимодействий

Один отказ может формироваться в раннем слое и реализовываться в позднем.
Одно окно тогда выглядит слабым, хотя пара сильна.

Для двух лучших непересекающихся окон `A` и `B` измерить:

```text
synergy = effect(A+B) - effect(A) - effect(B).
```

Если synergy воспроизводимо велика, разрешить два окна. Не добавлять второй
пик только потому, что он улучшил один маленький eval.

Также проверить взаимодействия:

- attention window + MLP window;
- routed experts + shared expert;
- full attention + linear attention;
- весовая интервенция + выбор направления.

## 8. MoE-диагностика

Для Qwen дополнительно логировать без сохранения текстов:

- top-k expert IDs по слоям и токенам;
- router probabilities;
- частоты экспертов на REFUSAL/SOFT/COMPLY;
- изменение маршрутизации после интервенции;
- conditional effect окна внутри каждого эксперта.

Полезные статистики:

```text
odds ratio expert_e | refusal
mutual information(expert_e, verdict)
mean router probability by verdict
bootstrap stability across prompts
```

Высокая ассоциация не доказывает, что эксперт несёт отказ: router может выбирать
его из-за темы запроса. Для верхних экспертов нужен причинный тест.

Если hotspot локализуется одновременно по слою и по небольшому набору экспертов,
следующий профиль может быть двумерным:

```text
λ(layer, expert) = layer_window(layer) × expert_scale(expert).
```

Это уже отдельная гипотеза; её нельзя смешивать с первым тестом новой кривой.

## 9. Optuna только после локализации

После coarse-to-fine скана пространство для одного компонента:

```text
center       — внутри подтверждённого интервала
log_radius   — небольшой диапазон вокруг найденного масштаба
amplitude    — 0..2.5
edge_power   — 1..6
shape        — bump или plateau, если бюджет позволяет
```

Старый `max_weight_position/min_weight_distance` не переиспользовать под новые
значения: их смысл изменится. Нужны новые имена параметров и новая study.
Старые фронтовые точки можно enqueue как baseline, если явно преобразовать их
профиль в новое представление или оставить старую форму отдельной категорией.

Нельзя продолжать старую study с изменёнными distributions: TPE уже обучился на
другом пространстве.

## 10. Честный A/B

Сравниваются:

```text
A: текущая палатка
B: компактный гладкий пик
C: гладкое окно с плато
```

Условия:

- одинаковый trial budget;
- одинаковые seeds;
- одинаковые направления и train prompts;
- одинаковые frozen eval prompts;
- одинаковый semantic judge;
- одинаковая perplexity выборка;
- одинаковые границы амплитуды;
- отдельный отчёт о runtime.

Победа — Pareto-доминирование или воспроизводимое улучшение выбранной рабочей
точки, а не лучший единичный trial.

## 11. Диагностические развилки

| Наблюдение | Вероятный вывод |
|---|---|
| статистический пик есть, причинного эффекта нет | пик является следствием или коррелятом |
| `A=1` помогает, `A=2` портит | нужно стирание, не инверсия |
| `A=2` заметно лучше `A=1` | поддержка гипотезы локальной инверсии |
| центр устойчив, радиус мал | локальное окно уместно |
| центр прыгает по категориям | нужны групповые направления или несколько окон |
| один слой нестабилен, окно 3–5 слоёв устойчиво | механизм распределён локально |
| window улучшает marker score, но не semantic verdict | scorer эксплуатируется |
| refusal падает, perplexity резко растёт | найден общий функциональный bottleneck, не хирургическая точка |
| разные компоненты требуют разные окна | schedules нельзя связывать |

## 12. Минимальный первый эксперимент

Для дешёвой проверки на Gemma:

1. выбрать одну семантически проверенную рабочую точку;
2. сохранить raw послойные агрегаты до нормализации;
3. просканировать attention и MLP окнами шириной 4;
4. для каждого окна испытать `A=1` и `A=2`;
5. на первом проходе использовать замороженное подмножество prompt IDs;
6. два лучших окна уточнить до ширины 1–2;
7. полный прогон на 234 prompts;
8. ручные/семантические verdicts;
9. perplexity и harmless/tech-sensitive контроль;
10. только после этого добавлять профиль в основной Optuna.

Этот эксперимент отвечает на главный вопрос до реализации сложной Bézier-
параметризации: существует ли вообще компактная причинная зона, которую выгодно
инвертировать.
