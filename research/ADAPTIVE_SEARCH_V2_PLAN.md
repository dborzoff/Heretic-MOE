# Adaptive Search v2: восстановление рабочей базы и план поиска

Дата: 2026-08-02.

## Цель

Вернуть основным производственным поиском доказанную схему, которой был найден
внутренний Gemma-2 кандидат t190, а поздние локализационные механизмы сохранить
как отключаемые исследовательские инструменты. Новая версия должна уменьшать
отказы при минимальной потере качества, сохранять полный журнал и позволять
восстановить любой trial после завершения исследования.

## Неподвижные требования

1. Не читать и не печатать тексты промптов и ответов в ходе инженерной работы.
2. Перед изменением `master` доказательно установить ревизию кода, конфигурацию
   и параметры поиска, которыми был создан t190.
3. Сохранить текущую позднюю историю в локальной ветке `test`; не удалять её и
   не переписывать до проверки достижимости всех коммитов.
4. Не терять незакоммиченные изменения и крупные исследовательские артефакты.
5. Каждый trial строится из чистой базовой модели; накопление правок между
   trials запрещено.
6. Optuna-журнал и типизированный sidecar остаются источником для повторной
   сборки любого trial, а не только автоматически выбранных финалистов.

## Этап 0. Установить точную базу t190

- Сопоставить время создания файлов модели с Git-историей.
- Найти коммиты, которые ввели расширенные границы, `FULL`, GPU perplexity,
  60 startup trials, multivariate TPE и чистый reset между trials.
- Проверить сохранённые конфигурации, журналы и provenance без чтения текстовых
  полей корпусов.
- Зафиксировать `t190_code_commit`, `t190_config_hash`, модель-источник,
  параметры trial и доказательства в отдельном provenance-файле.
- Не считать поздний документирующий коммит базой без подтверждения, что его
  код уже существовал до создания модели.

## Этап 1. Безопасно разделить ветки

- Создать/обновить локальную ветку `test` на нынешнем позднем HEAD.
- Сохранить относящиеся к поздней реализации отслеживаемые изменения отдельным
  WIP-коммитом в `test`; результаты и большие модели не добавлять в Git.
- Составить manifest незакоммиченных артефактов с путями и хешами.
- Только после проверки ветки и manifest перевести `master` на доказанную базу
  t190 и перенести в него этот план.
- Не выполнять `reset --hard`, очистку untracked или удаление результатов.

## Этап 2. Производственный глобальный поиск Adaptive Search v2

- Геометрия по умолчанию: один широкий `legacy_tent` на компонент.
- Нормировка по умолчанию: `FULL`.
- Границы: расширенная t190-область на всю глубину модели; автоматически
  масштабируется по числу слоёв, но наблюдательная локализация не является
  жёстким запретом для поиска вне найденного интервала.
- Startup: доказанный random-вариант остаётся контрольным; Scrambled Sobol
  реализуется как отдельный выбираемый sampler для честного A/B.
- После startup: multivariate TPE остаётся основным адаптивным алгоритмом.
- Две GPU запускают независимые A/B study с разными журналами: одна
  `random -> multivariate TPE`, вторая `Scrambled Sobol -> multivariate TPE`.
  Писать разными sampler'ами в один журнал нельзя: асинхронный порядок завершения
  смешивает политики и делает сравнение зависимым от скорости GPU.
- После одинакового бюджета различающиеся точки Парето можно перенести как
  queued seeds в новое контрольное study с единой полной метрикой.
- Число trials задаёт пользователь; автоматического лимита времени нет.

## Этап 3. Multi-fidelity как отдельный флаг

- Реализовать дешёвую, среднюю и финальную ступени без изменения геометрии.
- Значения дешёвой и полной ступени не смешивать как одну цель в одном фронте.
  Дешёвое discovery-study только отбирает параметры; принятые параметры заново
  измеряются в отдельном full-fidelity study.
- Дешёвая ступень: короткая генерация, быстрые числовые refusal/evasion proxy и
  малый PPL-пакет.
- Средняя ступень: расширенный пакет только новым точкам Парето и контрольной
  случайной доле, чтобы обнаруживать ошибочное раннее отсечение.
- Финальная ступень: полный frozen semantic review, 400x512 PPL, длинные ответы,
  export/reload и независимые регрессионные гейты.
- Multi-fidelity не должен считать quick-PPL окончательным: прошлые измерения
  показали смену знака между коротким и полным пакетом.

## Этап 4. Анализ журнала

- После startup и затем через настраиваемые интервалы строить text-free отчёт
  fANOVA/важности параметров и парных взаимодействий.
- Анализ не меняет распределения внутри действующего Optuna study.
- Если важность стабильна на bootstrap и разных prompt-блоках, создавать
  отдельное дочернее локальное study, seeded несколькими точками Парето.
- Хранить версию анализатора, входной диапазон trials, scorer hashes и
  неопределённость важностей.

## Этап 5. Локальные области и зональная компрессия

- После глобального поиска выбрать несколько разных точек Парето: removal-first,
  balanced и low-damage.
- Для каждой разрешить небольшое локальное TPE-study вокруг исходных непрерывных
  параметров; не заменять его обязательным деревом операций.
- Деление left/right, перекрывающиеся окна, exact probes, `+epsilon/-epsilon`,
  necessity/sufficiency и причинные трассы выключены по умолчанию.
- Они включаются только для сжатия доказанного родителя, по одному компоненту,
  с собственным бюджетом и обязательным сравнением с неизменённым родителем.
- Дополнительная зона принимается только при условном выигрыше и полном
  подтверждении; полезная локальная производная не считается достаточной
  правкой из чистой модели.

## Этап 6. Критерий выбора

- PPL выше `+0.5%` — жёсткий отказ кандидату.
- Область до `+0.3%` — предпочтительная, но разница меньше повторного шума
  считается ничьей.
- Refusal, redirect/evasion, epistemic limit, incoherence, truncation и PPL
  остаются отдельными полями, а не сворачиваются безвозвратно в один score.
- Небольшой остаточный refusal при нулевом измеримом повреждении может быть
  предпочтительнее нулевого refusal с заметной деградацией.

## Экспериментальная матрица

На одной и той же модели, frozen split и одинаковом бюджете сравнить:

1. t190 random startup + multivariate TPE (контроль);
2. Scrambled Sobol startup + multivariate TPE;
3. независимый параллельный A/B двух startup-дизайнов на двух GPU;
4. лучший из 1-3 с включённым multi-fidelity;
5. локальное study вокруг 2-3 точек Парето;
6. зональную компрессию только лучшего широкого родителя.

Главный результат — не лучший search score, а воспроизведённая после экспорта
точка, которая на одинаковом полном тесте Парето-доминирует t190 либо даёт
осознанно выбранный лучший компромисс.

## Что не переносить в основной автоматический путь

- наблюдательное дерево активаций как управляющий сигнал;
- реконструкцию широкой правки из независимо ранжированных точек;
- обязательную причинную трассу каждого trial;
- обязательную очередь split/exact/crossover до начала TPE;
- жёсткое исключение слоёв только по норме разности активаций;
- автоматическое увеличение числа зон без доказанного условного выигрыша.

Код этих механизмов сохраняется в ветке `test` и при необходимости переносится
как явно экспериментальный, чтобы старые журналы оставались воспроизводимыми.
