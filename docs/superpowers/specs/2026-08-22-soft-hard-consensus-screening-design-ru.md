## Этап A: английский межмодельный early-stop

Проверяются все `111191` preliminary HARD/SOFT-семейств. Каждая модель даёт
один короткий английский голос. Чтобы не закрепить позиционный bias, модели
циклически используют `code_permuted`, `code_shift_1`, `code_shift_2` и
`code_shift_3`.

Основные десять независимых моделей, в порядке от меньших к большим:

1. `google__gemma-2-2b-it`
2. `Qwen__Qwen3.5-2B`
3. `Qwen__Qwen2.5-3B-Instruct`
4. `mistralai__Ministral-3-3B-Instruct-2512-BF16`
5. `Qwen__Qwen3-4B`
6. `Qwen__Qwen3.5-4B`
7. `Qwen__Qwen3-VL-4B-Instruct`
8. `Qwen__Qwen2.5-VL-7B-Instruct`
9. `Qwen__Qwen3-8B`
10. `Qwen__Qwen3-VL-8B-Instruct`

`google__gemma-4-E4B-it` является независимым резервом для устойчиво
невалидного ответа. Qwen3.5-9B не участвует в подтверждающем голосовании,
поскольку ею построен preliminary-пул.

### Решение по строке

- `support` — модель выдала исходный preliminary-класс.
- `dissent` — модель выдала любой другой валидный класс.
- При `support >= 6` строка немедленно принимается в английский survivor-пул.
- При `dissent >= 5` строка немедленно отправляется в reject-пул.
- Невалидный вывод один раз повторяется альтернативным коротким форматом; при
  повторной невалидности используется резервная модель.
- Для каждой строки сохраняются все реально полученные голоса и причина
  остановки. Незапущенные модели не изображаются как голоса.

Таким образом, принятие означает подтверждение минимум `6/10`, а более четырёх
несогласных моделей гарантированно выбраковывают строку.

Модели запускаются последовательно по размеру. После каждого прохода из
следующей очереди исключаются уже принятые и уже отклонённые строки. Все
checkpoint'ы text-free и resume-safe.

## Категории

- Исходные S1-S14 PolyGuard механически отображаются в C01-C14.
- Категории HarmBench, StrongREJECT, ALERT, SALAD, Aegis, Do-Not-Answer и
  остальных источников сохраняются как provenance.
- WildJailbreak/AdvBench без категории размечаются только после прохождения
  английского early-stop.
- Категоризатор не меняет HARD/SOFT-решение. Допускается несколько категорий;
  неразрешённый конфликт получает `UNCLEAR_CATEGORY`, а не выдуманную метку.
- Отчёты показывают вход, survivors и reject по источнику и C01-C14.

## Этап B: переводы и строгий финальный консенсус

Только английские survivors переводятся в `ru`, `zh` и `ja`. Существующие
проверенные переводы PolyGuard переиспользуются. Остальные переводы создаются
существующим aligned-translation pipeline с неизменным `canonical_id`, затем
проверяются на exact coverage, порядок, непустоту и hash drift.

Каждый survivor прогоняется:

- на основных десяти моделях;
- на `en/ru/zh/ja`;
- по восьми форматным вариантам: четыре code и четыре word-order.

Для одной пары model/language класс считается устойчивым при `>=6/8`.
Семейство получает `clean HARD` или `clean SOFT`, если исходный класс
подтверждают минимум `6/10` моделей минимум на двух языках. Дополнительно
сохраняются per-language показатели, чтобы не называть строку чистой на языке,
на котором этот класс не подтверждён.

## Выходы

1. Полный immutable English archive всех `126869` строк.
2. English preliminary HARD/SOFT archive (`111191`).
3. English survivor и reject manifests с голосами и stop reason.
4. Aligned survivor dataset для четырёх языков.
5. Text-free полный финальный consensus.
6. Отдельные `clean_hard.jsonl`, `clean_soft.jsonl` и резервные holdout-пулы.
7. Матрицы source/category/language/model и SHA-256 каждого frozen-артефакта.

Тексты промптов остаются только в приватных dataset JSONL. Консоль, manifests,
checkpoints и отчёты не содержат тексты промптов или ответов.

## Отказоустойчивость

- Результат записывается атомарно после каждого batch.
- Resume вычисляется по `(model_id, row_id, variant)`.
- OOM повторяет только незавершённый batch с меньшим размером.
- Перед переходом к переводам проверяются exact coverage, отсутствие дублей,
  допустимые классы и соответствие source manifest hash.
- Preliminary, survivor и clean всегда являются разными явно названными
  состояниями.
